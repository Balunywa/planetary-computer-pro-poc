One click, then explore

Deploy StormLens in your subscription

Everything is provisioned and pre-wired by a single Azure deployment. You connect over Bastion, open VS Code (already loaded), and the site talks to your catalog.

Deploy

Stand up the environment

Click “Deploy to Azure”

Pick your components (GeoCatalog always; workstation, sample storage, AI agent, Aurora, and the web app are optional) and a supported region.

Connect over Bastion

Open the workstation → Connect via Bastion. There is no public RDP port.

Open “Start Here”

Double-click the desktop shortcut — VS Code opens the repo pre-loaded, signed in, with START-HERE.md guiding you.

Run the weather workflow

Open the hurricane forecast notebook (its .env is pre-filled) and run it top to bottom.

Explore in StormLens

Open this site’s Live Explorer, sign in, and view your collections on the map.

Run the web app

Two ways to host StormLens

🖥️

Locally on the workstation

The deployment drops the site on the VM and starts a local server. Or run it yourself:

cd C:\StormLens\webapp
python -m http.server 8080
# open http://localhost:8080
🌐

Azure Static Web Apps

Select the web app component and the template provisions a Static Web App and publishes these files to a shareable URL — the same experience as this page.

Sign-in setup. The Live Explorer uses Microsoft Entra ID (MSAL) from the browser, so it needs an app registration (client ID + redirect URI). The deployment can create one for you and write it into assets/app-config.js; otherwise paste your own client/tenant IDs there.
